# ADR 0022: platform configuration and primary color

Status: Accepted

## Decision

Administration → Configuration (`/administration/configuration`) manages platform-wide configuration. Its first section is Appearance. Only the built-in Administrator role can read the editor or save configuration; delegated `settings.manage` alone is insufficient. Endpoint and route enforce access, and the save store checks current role membership. Access responses expose `isAdministrator` for navigation; setup-only sessions do not receive this capability.

Store appearance in one seeded PostgreSQL row with an optimistic version token. The Application command validates a six-digit hex color and uses the existing dispatcher transaction. Infrastructure atomically changes color/version and records `configuration.appearance_changed` without payloads. Stale saves return 409 and preserve the editor draft; Undo changes uses a discard confirmation before restoring the saved settings. Selection applies the draft palette to the current page, so Save persists the command, accepts the returned version and confirms success without reloading.

A separate anonymous, no-store endpoint returns only the public primary color and login background preset ID, so branding applies before login too. Angular loads it once after runtime configuration and before rendering, with a five-second timeout and bundled-brand fallback. Saving does not broadcast or update existing pages; users receive the setting on their next full refresh.

Generate primary shades using sRGB relative luminance, retaining hue where possible. The dark-theme primary uses a lower luminance target than the earlier palette, reducing white mixing so configured colors remain richer and more vibrant. Semantic light/dark mappings remain in `brand.css`. Light and dark primary text/buttons have contrast margins above WCAG AA; pale, black and white inputs remain usable. Live preview uses the same generator in scoped light and dark samples and never changes the application theme. Browser-local theme and accessibility preferences retain their behavior.

## Extension points and upgrade

Named custom colors occupy a separate row below nine built-in presets: blue, violet, magenta, red, orange, emerald, cyan, lime and yellow. The shared palette supports at most 24 colors with stable IDs, unique case-insensitive names of 1–40 characters and six-digit hex values. A copied Helm right-side drawer and slider composition provides a saturation/brightness drag surface, keyboard-operated hue/saturation/brightness sliders and precise hex entry. The drawer uses the shared header/body/footer composition, keeps its single Use color action visible below a clearly spaced parameter stack, and isolates picker pointer gestures from drawer dragging. Slider groups place the label and current value directly above each track. Every interaction applies the draft palette to root brand tokens and updates preview cards with explicit light and dark semantic surfaces; Use color adds or edits a draft, while Escape restores the selected draft color. Leaving after discarding restores the saved root palette. The editor supports renaming and removal. Removing the selected custom color selects default blue and announces the change, with focus returned to Add custom color.

Store the bounded palette as a typed JSON array in a PostgreSQL jsonb column alongside the selected custom ID. Palette edits, selection and primary color share the existing transaction and optimistic version, so concurrent administrators cannot overwrite each other's changes. The server derives primary color from a selected custom ID, and removing the active custom color falls back to default blue. Requests omitting custom colors retain the existing palette for compatibility. Public appearance never exposes custom color names or IDs. Run the CustomBrandColors migration on upgrade; it preserves the existing primary color.

## Authentication backgrounds

Appearance owns separate right drawers with matching thumbnail radio blocks for gradient types and color presets, plus a single theme preview containing representative Spartan form controls alongside the login artwork for all 30 current FeralUI types and their 298 presets. Sky is one type; Blue sky remains the default. Selecting a type selects its first color preset, then the administrator can choose any palette belonging to that type. Selecting a block immediately updates the draft and closes its drawer. Both drawers use the shared Spartan drawer composition. Selection remains a draft until Save; Undo and stale-version handling cover both color and background. The public preset applies through the shared authentication layout to login, signup, bootstrap and account/recovery screens. Mobile keeps the existing form-only layout.

The `LoginBackgroundPresets` migration adds a bounded preset ID to the existing settings row, preserving existing color configuration and selecting Blue sky for upgrades. Application validates an explicit allowlist; omitted background fields retain the saved value for older clients. Save updates the background and audit change atomically with the existing version token. No URLs or executable configuration are accepted.

The owned Canvas host uses the builder's original rendering functions, shaders, palettes and motion parameters locally; see THIRD-PARTY-NOTICES for provenance. It is loaded lazily and capped at 30 frames/second and a 960-pixel longest edge (240 for thumbnails). Types that are static in the builder remain static. Thumbnails render a still frame. Animation stops offscreen, in hidden tabs, under either system or app reduced-motion settings, or using the visible Pause background control. Resize and route teardown are handled locally; renderer failures expose the preset's CSS gradient without blocking authentication. The bright artwork is independent of the application theme, and controls retain semantic theme surfaces.

`node tools/vendor-gradients.mjs <downloaded-bundle>` extracts the pinned builder's rendering dependency closure and generates the frontend catalog and Application allowlist together. The source bundle URL is recorded in THIRD-PARTY-NOTICES. Stored IDs encode type and preset; the eight original Sky IDs remain compatible, so expanding the catalog needs no additional migration or HTTP contract. Type labels and controls are translated; upstream artwork titles are preserved. When updating the source, review the extraction roots, default speeds and new type translations, and run focused persistence and rendering coverage. Keep renderer code and preset data bundled; changing appearance must never load third-party scripts at sign-in.

Run the DatabaseMigrator before starting the updated API. Add future typed configuration sections through Application contracts, explicit handlers/validators, focused Infrastructure persistence, versioned endpoints and localized Helm fields. Keep private configuration out of the public appearance DTO. Schema changes need generated EF migrations; contracts use the API exporter and Angular generator. Configuration is a baseline capability with no optional-module dependency. Scaffolds inherit it as part of the baseline; existing CI covers compilation, manifest/documentation validation and PostgreSQL tests.

Validate role denial (including delegated settings permission), CSRF, invalid colors, conflicts, reload persistence and transactional audit entries against PostgreSQL. Check generated palette contrast with boundary colors. Keyboard, responsive and both-theme browser accessibility checks require explicit permission before E2E execution.

The primary color recolors presets across every type by rotating their relative hues around the strongest palette color and scaling saturation to the primary color. The preset brightness structure and animation remain intact. Shared thumbnails, the theme preview and authentication screens use the same transformation. Existing primary-color and preset-ID persistence is sufficient; no additional stored palette or HTTP contract is needed. The shared control sampler replaces the login-form and separate light/dark appearance samples. It renders actual Spartan inputs, selection controls, badges and button variants so administrators can review the primary color and background together.
