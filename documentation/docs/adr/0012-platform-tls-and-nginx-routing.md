# ADR 0012: platform TLS and Nginx application routing

Status: Accepted

The Web image's Nginx is the application-facing proxy. It serves Angular and routes same-origin `/api/` requests to ApiService. Local Compose mounts the development certificate generated by `framework dev-init` into that container and exposes HTTPS on localhost:8443. Mailpit remains a local and test-only SMTP sink.

Production Nginx listens on plain HTTP port 8080 behind the web hosting platform. Coolify/Easypanel terminates public TLS, manages ACME certificates and redirects, and routes traffic to that port. The application stack does not contain a separate gateway service or public-certificate mounts. ApiService, BackgroundWorker, and PostgreSQL remain private.

ApiService trusts only the fixed Nginx container address as its immediate forwarded-header proxy. The hosting-platform ingress replaces untrusted external forwarding headers, and Nginx preserves its trusted client address for API rate limiting while reporting the platform-terminated public scheme as HTTPS. Deployments using a different network topology must update the trusted proxy address deliberately and must not expose the Web container directly to untrusted traffic.
