# ADR 0010: Spartan blocks and template design tokens

Status: Accepted

Enabled actionable controls share a pointer cursor through global semantic selectors, including wrapping choice labels. Disabled and inert controls are excluded. Text entry and resizing retain their specialized cursors, and copied Helm controls avoid default-cursor overrides on enabled actions. This keeps cursor feedback consistent without changing keyboard behavior or focus styling.

Use Spartan Sidebar 2 (inset navigation) for authenticated routes and Login 2 / Signup 2 (two-column forms) for authentication. Retain the existing credential, passkey, recovery and invitation flows. Navigation reflects available permissions; it contains no demonstration-only destinations.

Copied Helm components are the application control system. Compose fields, switches, checkboxes, tabs, tables, cards, alerts, empty states, menus and the responsive sidebar using their actual selectors. Checkboxes with supporting descriptions use a wrapping `hlmFieldLabel` so the entire checkbox field is one selectable area. Compact mutually exclusive choices use the copied Spartan tabs composition and the dashboard filter treatment: a muted inset list with a primary active pill. Selection moves the pill with a transform and size transition; reduced-motion preferences change it immediately. Confirmation prompts use the copied Spartan Alert Dialog composition and its default styling; form-based overlays use Spartan Dialog. Drawer headers use the semantic muted background and border tokens across light and dark themes. Native HTML remains appropriate for semantic structure, but adding an unknown Helm attribute to a native control does not style it. Brain remains the only headless dependency.

Right-side drawers reuse the card-panel visual system: the drawer is a muted rounded shell, its header uses panel spacing, and `hlmDrawerBody` plus `hlmDrawerFooter` form the inset semantic card surface. Drawer bodies align their top and horizontal content edges with the shared panel-header inset. Every right-side drawer uses this shared composition so its forms, filters, details and preferences inherit the same responsive spacing, radii, light/dark colors and focus behavior as page cards. The notification drawer retains its denser list-specific body inset and compensating edge treatment. Other drawer directions retain their native Spartan treatment.

Date entry uses the copied Spartan Helm date-picker composition rather than native date inputs. This keeps date selection, keyboard behavior, theme styling and culture-aware display consistent across browsers; feature code remains responsible for converting selected local calendar dates to API contract values.

Tabular application data uses the reusable `app-data-table` composition in `src/TemplateV4.Angular/src/app/shared/data-table.ts`. It follows Spartan's Data Table guide by combining the copied Helm table directives with TanStack Angular Table; feature pages provide typed column definitions and data, and interactive cells use Angular components through `flexRenderComponent`. New feature tables extend this composition instead of writing page-local table markup or introducing another grid library. Every data table is server-paginated, and every data-bearing column is server-sortable through the shared accessible column headers. Action-only columns are not sortable. Feature pages own the URL-backed sort column and direction, while APIs validate an explicit allowlist and apply a stable identifier as the secondary ordering.

Data-table panels share one horizontal inset, `--card-spacing` (four spacing units, 16px at the default scale), for their heading, filters, outer columns and pagination content. `workspace.css` automatically assigns that inset to headers of cards containing `app-data-table`, including compact density and small cards. The shared pager finishes the card surface with a full-width semantic card background matching the table rows, matching bottom radii and equal compact vertical padding. It follows the table without a layout gap; results remain left and controls right, stacking on mobile. Feature pages must reuse this composition rather than compensate with local spacing overrides.

Shared server pagination defaults to 10 rows. Selectable page sizes use the shared 5, 10, 25 and 50 row options; pages do not define competing local defaults.

Keep project branding in `src/TemplateV4.Angular/src/brand.css`: complete primary and neutral shade palettes, light/dark semantic color mappings, chart colors, and separate heading/body font stacks. The default project palette uses blue as its primary color. Components consume semantic tokens rather than palette shades so a project can be rebranded without page-level overrides. Keep global Tailwind/Spartan setup and non-brand base styles in `src/TemplateV4.Angular/src/styles.css`, and layout dimensions in `src/TemplateV4.Angular/src/design-tokens.css`. Tailwind spacing, typography and radius variables provide the shared scales used by copied Helm controls. Authentication shares one layout and local artwork; no external image origin is required by CSP. The photo is the reference block's Unsplash image, recorded in THIRD-PARTY-NOTICES.

The inset main and sidebar are siblings. Desktop navigation uses a permanent 4rem icon rail beside an independently resizable label panel (12rem default, 0–20rem range). The copied Helm sidebar's panel layout reserves the combined width; collapsing removes only the label panel from layout and keyboard navigation. The rail retains all permission-filtered destinations, brand and account menu. Selecting the active rail destination toggles the panel; selecting another opens it and navigates. Future navigation hierarchy changes extend this composition. The divider has a pointer-following 2rem resize icon, translucent 5rem vertical guide and localized tooltip. Pointer capture supports dragging beyond the divider; Escape restores the original state. Arrow keys resize in half-rem steps, Home collapses, End selects the maximum, and double-click resets. Dimensions remain centralized in design tokens and persisted in rem so text-size adjustments scale the rail, panel, icon and guide together. Panel width and open state synchronize through local storage, with a cookie retaining initial open state. Storage failures leave the page functional. Mobile retains the existing sheet and is not resizable.

The mobile sheet receives a localized accessible title, and selecting navigation closes it. The account menu owns account actions and sign-out. Appearance and language controls remain accessible before sign-in and from a localized Spartan drawer opened by an ng-icons settings button in the authenticated header. The drawer adds browser-local text size, contrast, motion and interface-density preferences, plus one reset action for every setting and the sidebar width/open state. These preferences apply through root data attributes, synchronize across tabs and are initialized before Angular renders.

The authenticated header owns the shared Spartan breadcrumb composition. Route data supplies stable localized labels, URL segments provide the automatic fallback, and pages may replace the trail through the shared breadcrumb service for runtime entity labels. Ancestors remain navigable, the current page is non-interactive, long trails collapse their middle levels on mobile, and the named back action uses browser history rather than assuming the breadcrumb parent is the previous page.

Validation includes production builds under the deployed CSP, keyboard/mobile navigation, WCAG checks in both themes, and focused registration/settings tests. Backend verification requirements are recorded in ADR 0009.
